Signup Wizard: Functional Requirements

Author: Muhammad Hashaam · Version: 1.0 · Status: Implemented

1. Purpose

New users abandon long signup forms. This feature splits signup into three short steps with clear, immediate feedback, so more users finish and fewer support tickets come from bad data.

2. Scope

In scope: the client-side form, validation, progress indicator, draft saving and review step.
Out of scope: the back-end account API, email verification and payment. The form is ready to POST to an endpoint.

3. User stories

  • As a new user, I want to see how many steps are left, so I know how long signup takes.
  • As a user who made a mistake, I want to be told exactly what to fix and where.
  • As a user who refreshed by accident, I don't want to retype everything.
  • As a screen-reader or keyboard user, I want to complete signup without a mouse.

4. Functional requirements

IDRequirementAcceptance criteria
FR-1The form is split into Account, Profile, Plan and Review steps.Only one step is visible at a time.
FR-2A progress indicator shows completed, current and upcoming steps.The current step has aria-current="step".
FR-3Each field is validated on blur and when the user continues.Invalid fields get aria-invalid="true" and a message under the field.
FR-4If a step has errors, an error summary appears at the top.The summary gets focus and links to each invalid field.
FR-5The password must have 8+ characters, a letter and a number, and a strength meter is shown.The meter updates as the user types. The password can be shown or hidden.
FR-6Moving between steps sends focus to the first field of the new step.Keyboard users never land at the top of the page.
FR-7A draft is saved for the browser session.After a reload, all fields except the passwords are restored.
FR-8The review step lists every answer, with links to edit each step.User input is shown as text and never parsed as HTML.
FR-9Submitting sends the data to the account API (stubbed in this demo).Nothing is submitted until all steps are valid.
FR-10A confirmation screen appears on success and the draft is cleared.The confirmation gets focus and greets the user by first name.

5. Non-functional requirements

  • Accessibility: WCAG 2.1 AA, with labels on every input and colour never the only signal.
  • Performance: no dependencies, under 20 KB in total, Lighthouse 90+ on mobile.
  • Compatibility: the latest two versions of Chrome, Edge, Firefox and Safari, from 320 px wide up.

6. Test checklist

  • Continue with empty fields shows the summary, and its links focus the right fields.
  • Mismatched passwords show "Passwords do not match."
  • Reloading on step 2 restores the email and name but not the password.
  • The whole flow can be completed with the keyboard only (Tab, Space, Enter).
